## 🔴 Critical Issues (Phải sửa ngay)

### 1. CORS mở rộng (Mở toang cửa nhà)
- **File:** `backend/main.py` (dòng `allow_origins=["*"]`)
- **Nguy hiểm:** CORS đang được cấu hình cho phép MỌI domain (`*`) truy cập vào API. Nếu đưa lên server thật (Production), bất kỳ trang web độc hại nào có thể gọi API của bạn thay mặt cho người dùng (tấn công CSRF).
- **Cách sửa:** Đổi thành danh sách các domain cụ thể được phép truy cập (VD: `["https://tts-studio.com", "http://localhost:5173"]`).

## 🟡 Warnings (Nên sửa)

### 2. Thiếu "Mục lục" (Index) trong Database gây chậm truy vấn
- **File:** `backend/models.py` (Bảng `GeneratedAudio`, `BatchJob`, `SavedVoice`...)
- **Nguy hiểm:** Các bảng này đều lưu cột `owner_id` (ID của user) để biết file của ai. Tuy nhiên bạn đang KHÔNG đánh `index=True`. Khi lượng data lớn lên đến hàng triệu file, mỗi lần hiển thị trang Library, Database sẽ phải lật tung toàn bộ dữ liệu (Full table scan) để tìm file của user đó, khiến app rất chậm.
- **Cách sửa:** Thêm `index=True` vào cột `owner_id` trong tất cả các model.

### 3. Khóa bí mật (JWT Secret) dễ bị lộ
- **File:** `backend/auth.py`
- **Nguy hiểm:** Đang có code `JWT_SECRET = os.getenv('JWT_SECRET', 'change-me-in-production')`. Mặc dù đã dùng biến môi trường, nhưng nếu quên config biến này trên server, hệ thống sẽ dùng chuỗi mặc định dễ đoán. Hacker biết được chuỗi này có thể tạo token giả và đăng nhập thành bất kỳ ai.
- **Cách sửa:** Bắt buộc hệ thống phải báo lỗi sập server (crash) nếu không tìm thấy `JWT_SECRET` trong `.env` khi chạy production, thay vì dùng chuỗi fallback.

### 4. Thiếu bảo vệ chống Spam Login (Rate Limiting)
